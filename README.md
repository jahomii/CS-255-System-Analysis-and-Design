#CS 255 System Analysis and Design

My Client DriverPass desired a system that allowed users to purchase packages and make reservations for driving lessons. Their end goal was to help users get their licenses by providing DMV-accurate tests and in-person driving lessons with real instructors. I think I did particularly well when it came to analyzing the needs for DriverPass's system. 

If I were to revise a part of my documents, I think I would pick my sequence diagram specifically. I think it could've used more detail in the ways I depicted the DriverPass system communicating with itself, and the types of tasks different system users would perform, like the Admin's ability to download files.

I interpreted the users' needs based on what I found in the documentation of their proposed system. There were specific functions that were stated outright, like the need to manually insert new packages and for users to make reservations. Based on these functions, you can then employ some basic reasoning skills to conclude that the admin and IT officer accounts should have special privileges to add packages, and the users should have no access to these privileges. Considering the users' needs is important when designing because the system you're making is for them to operate, so if they can't utilize it in the way they need to, then they won't use it at all. 

I approach designing software similarly to how I approach art. I hear the idea and gather as much information as I can before I begin executing. I gather together my sources, references, and inspirations and lay the groundwork for the idea. In this case, I looked at similar systems to see how they function after I read the admin's needs for the system. Then I wrote down what I found to be most important and effective as well as any new ideas that might benefit the system. I would use these strategies in the future to analyze and design a system as well as convey my current analysis to another person and hear their interpretation of the idea. It is always useful to get a second opinion.
